# Project rules

- Work in small steps. Change only what the current step in `build_step.md` asks for.
- Never commit or print secrets from `.env`.
- Explain each file you create in two or three sentences.
- Ask before adding any dependency not listed in `SPEC.md`.
- Keep functions short and name them clearly.
- After each step, update `README.md` and add a section to `EXPLANATIONS.md`. The README is the final project document: keep the Status table, How it works, Usage, Project layout and Known limitations accurate, and add the step to the Build log. Only put numbers from real runs in it.
- Don't commit unless the user asks.
- The model provider is Google Gemini (`GOOGLE_API_KEY`).
